### 적용 내용 (`SearchWithWin32Async`)

1. **디렉터리당 열거 1회.** `folder\*질의*`(매칭용)와 `folder\*`(하위 폴더 수집용)로 두 번 열던 것을 `folder\*` 한 번으로 통합. 이름 매칭은 `PathMatchSpec` 으로 인프로세스 처리하고, 같은 패스에서 매칭 결과와 하위 디렉터리를 함께 수집한다.
2. **병렬 BFS.** 재귀 `await` DFS → 레벨 단위 `Parallel.ForEach`(최대 `min(코어수, 8)`). 결과 컬렉션 변형은 `resultsLock` 으로 직렬화.
3. **디렉터리별 `Task.Run` / `WithTimeoutAsync(5초)` 제거.** 취소는 검색 전체 `CancellationToken` 하나로 통일. 5초 초과 가지가 조용히 누락되던 정확성 버그도 함께 해소.
4. **바로가기 중복 검사 O(n²) → `HashSet`.** 인덱서가 먼저 넣은 항목까지 포함해 시작 시 1회 채운다.
5. **`SearchTick` 경쟁 조건 수정** (`d462c99`). `ShellViewModel.SearchAsync` 의 tick 핸들러는 첫 `await` 이전에 `results`(평범한 `List<T>`)를 동기적으로 복사한다. 병렬화 이후 그 복사 중에 다른 워커가 `Add` 할 수 있어 `InvalidOperationException` 가능 → tick 발화를 `resultsLock` 안으로 이동.

보존한 동작: 숨김/시스템/점 파일 필터 규칙, `hiddenOnly` 의미, 바로가기 `ParseLinkAsync` 지연 채움, `maxItemCount` 조기 종료, `SearchTick` 발화 주기(32건·이후 300건마다).

## 4. 빌드 절차

### 검증용 Debug 빌드

```
msbuild -restore src\Files.App\Files.App.csproj -p:Configuration=Debug -p:Platform=x64 -v:quiet -clp:ErrorsOnly
```

msbuild 경로: `C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\MSBuild\Current\Bin\amd64\MSBuild.exe` (BuildTools 18, Professional 아님 — AGENTS.md 기재와 다름)

### 배포용 포터블 릴리즈 빌드 → `build\` (기본 절차)

```
msbuild -restore src\Files.App\Files.App.csproj -t:Publish ^
        -p:Configuration=Release -p:Platform=x64 -p:FilesPortable=true ^
        -v:quiet -clp:ErrorsOnly
robocopy "src\Files.App\bin\Release\net10.0-windows10.0.26100.0\publish" "build" /E
del /q build\*.pdb
```

- 퍼블리시 프로필 `Properties\PublishProfiles\win-x64.pubxml` 이 `PublishAot=true`, `RuntimeIdentifier=win-x64`, `SelfContained=true` 를 설정한다.
- **산출 경로 주의:** `PublishDir` 이 `bin\$(Configuration)\$(TargetFramework)\$(RuntimeIdentifier)\publish\` 로 정의돼 있으나 실제로는 **RID 세그먼트 없이** `bin\Release\net10.0-windows10.0.26100.0\publish\` 에 떨어진다.
- `build\Files.exe` 는 Native AOT 단일 실행 파일(약 52 MB)이다. 일반 Release 빌드의 관리형 `Files.exe`(약 0.6 MB) + `Files.dll` 을 여기에 덮으면 .NET 런타임 DLL이 없어 **실행되지 않는다.**
- `robocopy /E`(`/MIR` 아님)를 쓸 것. `build\` 의 `LICENSE`, `LICENSE-MIT`, `LICENSE-MPL`, `THIRD-PARTY-NOTICES.md`, `SOURCE-CODE.txt`, `README-portable.txt`, `licenses\`, `Data\` 는 퍼블리시 산출물에 없으므로 보존된다.
- 퍼블리시가 딸려 보내는 `*.pdb` 는 삭제한다(포터블 패키징 제외 대상).
- 패키징 시에는 `.github\scripts\Add-PortableNotices.ps1 -BuildDirectory build -SourceRevision <40자 SHA> -ReleaseTag vX.Y.Z` 를 돌린다.

### 일반 Release 빌드(단독 실행 테스트용)

```
src\Files.App\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\Files.exe
```

## 5. 작업 환경 제약 (Cowork 세션 기준)

이 저장소를 Cowork에서 다룰 때 반복해서 부딪힌 것들이다.

- **`device_bash` 사용 불가.** 9월 8일 Windows 업데이트 이슈로 연결 폴더가 마운트되지 않는다. 대신 `windows-shell__run_process` 를 쓴다.
- **명령당 60초 하드 제한.** 초과하면 프로세스 트리가 종료된다. 긴 빌드는 `schtasks` 로 분리해야 한다:
  1. 배치 파일을 `artifacts\_build.cmd` 로 기록(gitignore 대상)
  2. 공백 없는 경로로 복사 — `copy _build.cmd C:\Users\CHANGH~1\AppData\Local\Temp\fb.cmd` (`/tr` 에 공백 경로를 주면 `0x80070002` 로 실패)
  3. `schtasks /create /tn ... /tr <공백없는경로> /sc once /st 23:59 /f` → `/run`
  4. 로그 파일을 `timeout /t 55 & type` 으로 폴링
  5. 끝나면 배치·로그·예약 작업 정리
- **`start` / `start /b` 는 무용지물.** 래퍼가 프로세스 트리를 잡고 있어 타임아웃 시 함께 죽는다.
- **PowerShell은 이 브리지에서 출력이 전혀 오지 않고 실행도 안 되는 것으로 보인다.** `.ps1` 스크립트는 직접 돌리지 말 것.
- **`VsDevCmd.bat` 호출은 배너만 찍고 종료 코드 1로 죽는다.** 다행히 AOT 퍼블리시는 Dev 환경 없이도 성공했다.
- **`cmd /c "..."` 문자열 안의 따옴표가 래퍼에서 망가진다.** argv 모드를 쓰거나, `cwd` 파라미터로 디렉터리를 지정해 따옴표를 아예 피한다.
- **`device_commit_files` 가 간헐적으로 `fetch or write failed` 를 낸다.** 이때 `NativeMethods-1.txt` 같은 중복 이름 찌꺼기가 남을 수 있으니 이후 `git status` 로 확인할 것.
- `where`, `attrib`, 셸 모드 `git` 등 일부 명령은 출력이 캡처되지 않는다. `git` 은 argv 모드로 호출할 것.
